# 01 产品定义

**一句话：一个真人，混在一群 AI 玩家里跑团。**

---

## 1. 为什么做

- 我喜欢跑团，但凑不齐人、找不到 GM；
- 市面上的 AI 跑团大多是“1 真人 + AI GM”，缺少 **AI 队友互相演** 的乐趣；
- 我需要一个 GitHub 作品：能展示多智能体、规则、随机、移动端产品设计，而且我自己愿意反复玩。

---

## 2. 给谁做

| 用户 | 需求 |
|---|---|
| **我（第一用户）** | 随时开一局 15–20 分钟；AI 队友有私心、会吐槽、会拒绝；每次有意外 |
| **GitHub 访客** | 5 分钟看懂；能读真实归档；能理解设计取舍 |
| **AI/TRPG 爱好者** | clone 后填 API 就能玩；能提 issue/PR |

---

## 3. 产品定位

**个人娱乐 + GitHub 作品。**

- 不是商业产品：不追求付费、版号、规模；
- 不是真人多人：只做 1 真人 + AI 队友；
- 不是 AI 小说：小说只是跑团过程的副产品；
- 不是聊天 App：有桌子、有骰子、有场景目标、有失败。

**一句话卖点：**

> **你不是一个人在跑团，你是一个真人混在一群 AI 玩家里。**

---

## 4. 目标

1. **好玩**：我自己至少玩 5 局，每局有 1–2 个“没想到”的时刻；
2. **像跑团**：有桌子、有 BP、有 GM、有真骰子、有场景目标；
3. **有性格**：GM/BP 会吐槽、会拒绝、会善变，不是应声虫；
4. **可展示**：Android 能跑，仓库有真实归档、README、Demo 视频；
5. **可维护**：一个人能在 4–6 周做出 MVP。

---

## 5. 非目标

| 不做 | 原因 |
|---|---|
| 商业发行/付费/版号 | 个人项目 |
| 真人多人联机 | 技术复杂，非核心 |
| 语音房/实时语音 | 成本高，MVP 不做 |
| 3D/VTT 地图 | 工程量大，文本足够 |
| UGC 市场 | 审核/分成/运营 |
| 自定义剧本生成（MVP） | MVP 只做入口，先做好一个固定剧本 |
| Mock 模式 | 无 API 就是固定内容；用真实归档代替 |
| 桌面端 | 移动端优先，Android 先做 |

---

## 6. 平台

| 项 | 结论 |
|---|---|
| 首选 | **Android**（Flutter，竖屏） |
| 后续 | iOS |
| 不做 | Windows/macOS 桌面端 |
| 屏幕 | 竖屏 9:16；单手可操作 |
| 网络 | 需要 API 才能实时生成；无 API 时只能看归档 |

---

## 7. 成功标准

| 指标 | 目标 |
|---|---|
| 我自己玩 | ≥ 5 局 |
| 单局时长 | 15–20 分钟 |
| 每局“意外时刻” | ≥ 2 个（吐槽/拒绝/失败/反转） |
| BP 像角色 | 不出现“我是 AI/作为语言模型” |
| 骰子可信 | 结果与日志一致，不能被 LLM 改 |
| 访客看懂 | 读 README + 示例归档，5 分钟内理解 |
| 访客能玩 | 填自己的 API key，3 分钟内进入第一句 |
| 单局成本 | < ¥5 |

---

## 8. MVP 范围

**只做：**

- 1 个剧本《顾先生的晚宴》；
- 1 个场景：门廊；
- 1 真人 + 2 BP（Stella/老陈）+ GM + 1 NPC（顾先生）；
- 四屏：首页 / 选择剧本 / 制卡 / 跑团；
- d100 检定 + 骰子卡；
- 插话 + 吐槽 + 拒绝；
- 团本历史归档；
- 设置（API/模型/文字速度/归档隐私）。

**不做：** 3–6 人、完整三幕、多结局、自定义剧本生成（只做入口）、语音、头像生成、分享链接。

---

## 9. 约束

| 约束 | 说明 |
|---|---|
| 单人开发 | 4–6 周 MVP，必须砍范围 |
| 个人娱乐 | 不追求商业级稳定 |
| 成本 | 模型费用自付，单局 < ¥5 |
| 版权 | 原创剧本/规则，不用 CoC/D&D 专有内容 |
| 无 Mock | 不维护两套逻辑；用真实归档展示 |
| 隐私 | API key 本地保存；归档默认私密 |

---

## 10. 风险

| 风险 | 对策 |
|---|---|
| AI 太客气/不好笑 | 把“吐槽”写进 GM/BP 规则；给角色目标/秘密/脾气 |
| AI 出戏/说教 | 禁止“我是 AI”；用剧情内拒绝代替系统提示 |
| 范围膨胀 | MVP 锁定 1 剧本/1 场景/3 人/四屏 |
| 无 API 不能玩 | 仓库提供真实示例归档；README 说明需要 key |
| 手机屏幕小 | 桌子 + 对话框 + 插话按钮，信息分层 |
| 版权 | 原创《顾先生的晚宴》 |

---

## 11. 需要确认

1. MVP 就做“1 真人 + 2 BP + GM + 1 NPC”？
2. Android 优先、竖屏，可以吗？
3. 无 API 时只给“示例归档”，不做 Mock，可以吗？
4. 归档默认私密、用户可开放，可以吗？
5. 首版只做门廊场景，可以吗？
