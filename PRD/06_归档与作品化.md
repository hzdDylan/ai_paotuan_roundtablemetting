# 06 归档与作品化

**一句话：没有 Mock；用真实归档证明它真的能玩。**

---

## 1. 为什么不做 Mock

- 没有 API 时，AI 不会真的说话；Mock 只是假数据；
- 维护两套逻辑（真/Mock）成本高；
- 读者想看真实效果，不想看“演示假数据”；
- 所以：**不做 Mock，做「团本历史归档」**。

---

## 2. 团本历史归档

### 2.1 什么时候生成

- 每局结束自动生成；
- 中途退出也可以“保存当前进度”，但不叫归档；
- 归档不可修改（可删除/导出）。

### 2.2 归档里有什么

| 内容 | 说明 |
|---|---|
| 基本信息 | 日期、剧本、时长、参与人数 |
| 队伍 | 你 + BP 的名字/头像/角色卡 |
| 完整 transcript | 谁在什么时候说了什么 |
| 骰子日志 | 技能/目标/骰值/结果 |
| 关键选择 | 你做过的重要决定 |
| 结局 | A/B/C/D + 一句话 |
| 高光时刻 | 自动标记 3–5 个（吐槽/大失败/反转） |

### 2.3 开放与否

- 默认：**私密**；
- 每条归档独立开关；
- 开放后：出现在「记忆回廊 · 公开」列表，可导出分享；
- 关闭后：只在本地；
- 删除：二次确认，彻底删除。

### 2.4 记忆回廊

- 首页第三个按钮；
- 列表：日期/剧本/队伍/结局/开放开关；
- 点开：读 transcript、看骰子、回放；
- 操作：开放/关闭、导出 Markdown/JSON、删除。

### 2.5 示例归档

- 仓库内置 1 个**真实跑出来的归档**（不是编的）；
- 放在 `samples/`，含 transcript + 骰子日志 + 角色卡；
- 没有 API key 的人也能读；
- README 里直接链接。

> 这就是“无 API 也能体验”的方式：**看真实归档，而不是看假 Mock。**

## 3. GitHub 作品化

### 3.1 README

```markdown
# 一人成团（Party of AIs）

> 一个真人，混在一群 AI 玩家里跑团。

![demo](docs/demo.gif)

## 这是什么
- Android 竖屏
- 1 真人 + 2–5 BP + AI GM
- 桌子 + 对话框 + 插话按钮
- 真骰子、吐槽、拒绝、善变
- 每局自动归档

## 先看一局
- [示例归档](samples/xxx.md)（无需 API）
- [Demo 视频](...)

## 跑起来
需要自己的 API key；没有 key 只能看示例归档。

## 架构
（Mermaid 图）

## 设计取舍
- 为什么不做 Mock
- 为什么 BP 要会吐槽/拒绝
- 为什么骰子要服务端
- 为什么移动端优先

## 评估
- 20 局 / 指标 / 坏局分析

## 限制
- 1 个剧本/1 个场景
- 无语音/地图/多人
- AI 偶尔出戏

## License
代码 MIT；剧本 CC-BY-NC 4.0
```

### 3.2 Demo 视频（3–5 分钟）

1. 首页五个按钮；
2. 制卡：属性/上传图/物品；
3. 跑团：桌子、对话框、BP；
4. 你做一个离谱操作 → GM/BP 吐槽；
5. 骰子失败 → 你插话 → 反转；
6. 归档 → 记忆回廊 → 开放开关。

**重点展示“吐槽”和“插话”，这是差异点。**

### 3.3 评估

| 指标 | 目标 |
|---|---|
| 20 局 | 门廊场景 |
| 每局吐槽次数 | ≥ 1 |
| 每局拒绝/善变 | ≥ 1 |
| 信息泄露 | 0 |
| 骰子篡改 | 0 |
| AI 出戏 | 0 |
| 单局成本 | < ¥5 |
| 单 beat 延迟 | < 8s |

**坏局要保留：** 不好笑/冷场/出戏的 transcript + 原因 + 修复，比好局更能说明问题。

## 6. 风险

| 风险 | 对策 |
|---|---|
| AI 不吐槽/太客气 | 把吐槽写进 GM/BP 规则；给角色脾气；示例进 prompt |
| 吐槽过度/冒犯 | 只吐槽行为，不攻击玩家；每场景 1–2 次 |
| 手机屏幕小 | 桌子+对话框+插话，信息分层；历史进记录 |
| 无 API 不能玩 | 示例归档 + README 说明 |
| 归档隐私 | 默认私密；每条独立开关 |
| 范围膨胀 | 锁定 1 剧本/1 场景/3 人/四屏 |
| 版权 | 原创《顾先生的晚宴》 |
